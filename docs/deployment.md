标准服务入口会在打开数据库前占用数据目录中的 `.hostlet-instance-lock`，拒绝另一标准实例使用同一目录。正常关闭会在请求和异步工作结束后释放占用；强制结束或崩溃可能留下该目录，服务不会自动认定它已失效。恢复时，运维须先确认所有使用该数据目录的服务和其他写入者均已停止，再仅移除该占用目录及其中的 `owner.json`，然后启动服务。不要凭 PID 或时间单独判断进程已停止；不要删除数据库、应用文件或其他目录。该保护要求可信运维和支持原子目录创建的本地文件系统，不能阻止绕过标准入口直接写入数据的进程。开发环境的强制重启也可能留下占用标记。

删除历史版本前，服务会短暂进入维护状态，等待已有访问和异步操作结束，再重新检查权限及版本并清理文件；期间受保护的请求可能收到 503 并应稍后重试。无权删除的成员在进入维护状态前被拒绝。若已有传输缓慢，等待可能持续至传输结束或超时。

发布中断后，启动时会根据发布记录清理未提交的暂存文件，并保留已提交版本；记录中的路径不匹配或已提交文件缺失时拒绝启动。新版上传的原始临时文件在写入内容前记录，启动时也会在独占状态下清理记录中的残留。旧版本产生的无记录残留，以及创建空暂存目录或空临时文件后、写入记录前中断留下的空项目不属于自动恢复范围；应停机检查后人工处理，不要按名称批量删除。上传临时文件及尚待恢复的残留可能占用配额统计之外的磁盘空间，应监控磁盘容量。

## 域名和信任边界

示例假定管理端为 `admin.example.org`，旧版页面为 `pages.exampleusercontent.net`，工作空间页面为 `*.apps.exampleusercontent.net`。后两者的可注册域是 `exampleusercontent.net`，与管理端的 `example.org` 不同；实际配置必须替换为自己控制的两个不同可注册域，不能仅使用同一可注册域下的不同子域。工作空间页面域通过 DNS 通配符指向代理，并提供覆盖通配符的 HTTPS 证书；旧版页面和管理端也需要各自匹配的证书。示例要求内容证书同时覆盖旧版页面和工作空间通配符。所有地址仅是占位示例。

示例 Nginx 是唯一公网入口，Compose 不发布 HTTP 端口，不进行 HTTP 到 HTTPS 重定向；可在外部使用 DNS-01 申请和续期证书。HTTPS 默认发布宿主机 443，设置 `HTTPS_PORT=30006` 等可改用其他空闲端口；非 443 端口必须同时写入 `ADMIN_ORIGIN`、`PUBLIC_BASE_URL` 和 `APPS_DOMAIN`，并确保 DNS、证书及外部访问配置匹配。容器中 3000 和 8080 端口不发布到宿主机：管理域转发 3000，内容域转发 8080，原始 Host 原样转发。未知域名拒绝，工作空间后端还会校验具体页面 Host。管理页面使用 `Referrer-Policy: strict-origin`，以便票据表单提交携带可验证的管理 origin；代理不得将其改为 `no-referrer`，否则浏览器会发送 `Origin: null` 并被拒绝。不要通过 CDN、负载均衡器或其他代理直接套用此配置；另行设计可信链及客户端 IP 处理，不能信任客户端自行提供的转发头。

Compose 固定 Nginx 后端地址 `172.29.25.2`，应用仅将此地址设为 `TRUSTED_PROXY_IPS`；Nginx 覆盖客户端提供的转发头。使用前确认子网 `172.29.25.0/24` 不与宿主或其他网络冲突；如修改，必须同步修改 Compose 中网络、代理地址及可信代理地址。Docker 宿主、拥有 Docker 权限的用户或加入该网络的其他容器可能直连后端，未发布端口并不隔离这些主体：仅允许可信运维控制宿主和 Docker，不允许其他容器加入网络，并配置宿主防火墙及网络策略阻止来自其他网络的后端直连。不要将后端端口或 Docker 网络开放给不可信主体。独立 IP 白名单无法替代网络隔离。

## 监控与告警

在可信监控系统中分别检查管理域的 `GET /api/health` 和内容根域的 `GET /health`：正常响应为 HTTP 200，维护期间为 503。连续失败或超时应通知运维，并结合容器状态、磁盘剩余空间及备份是否按期完成设置告警；短暂维护可能触发告警，需结合计划维护窗口处理。这些接口仅表示请求路径可用，不检查 SMTP、数据库完整性、证书续期、某个私有应用或备份可恢复性；应分别监控证书到期、邮件投递、磁盘和备份，并定期在隔离环境执行恢复演练。

应用自身会把脱敏后的接口请求结果写入数据目录的 `security-logs/`，默认按 UTC 日期轮转并保留 180 天。用 `SECURITY_LOG_RETENTION_DAYS` 调整期限，但该默认值不自动证明满足任何特定地区的法定留存要求。日志只记录粗粒度路由模板、状态、耗时和服务端解析出的来源地址，不记录查询参数、请求体、Cookie、密码、令牌或文件名。必须把日志目录纳入备份、磁盘容量和异常写入监控，并限制为运维可读；完整字段、局限和接入要求见[安全日志说明](security-logging.md)。这不能替代集中式安全监测、不可篡改保存或告警系统。

启用多用户和应用域后，实例管理员可在平台管理页面查看账号邮件、保留策略扫描和临时记录清理的最近结果及失败次数；同一管理员会话也可读取管理域 `GET /api/platform/operations`。状态只保存在进程内，重启后清零，不含邮箱、令牌或错误原文。账号邮件“成功”仅表示发送器接受请求，不保证送达；保留扫描成功也不表示发生了实际发送或删除。此页面不会主动告警，持续监控需在可信系统中结合外部探测及安全的认证方式实现，避免采集或泄露管理员会话。

账号写请求默认按 IP 和接口限制为每 15 分钟 20 次，所有账号写请求合计每 15 分钟最多 10,000 次，且最多同时处理 16 个账号操作；达到上限返回 429，读取当前会话不占用这些限额。限制保存在单进程内并在重启后重置，较慢的邮件服务也会占用并发名额；公开实例仍需在可信入口按实际容量设置额外限流和监控。

账号页面提供注销入口。用户须再次输入当前密码；服务进入维护窗口后先将注销任务持久记录，再删除个人应用的数据库记录和文件，最后清理团队成员关系、其他空间加入申请、账号及内容会话并匿名化账号。删除多个个人应用时若进程中断，启动会在接受请求前恢复任务；恢复失败则维护门保持关闭，不会继续运行半完成状态。团队最后一名所有者不能注销，必须先转移所有权。账号原始邮箱不会再被登录或注册记录引用，内部保留一条匿名化的用户 ID 作为团队内容、历史审计和外键锚点；已经生成的备份、管理员治理记录和依法需保留的记录不会被该在线操作追溯删除。自部署运营者仍须在隐私说明中披露具体保留范围、权利请求渠道和备份处理方式。本机隔离浏览器已验证最后所有者阻止和成功注销界面，临时 HTTP 集成测试验证了多应用中断恢复、清理与重新注册；这不替代目标部署环境中的邮件通知、备份处理和真实数据演练。

管理员可以查看空间配额来自平台默认值还是单独配置，并将单独配置恢复为平台默认值。配额变更记入管理员审计；降低额度不会删除已有内容或取消已预留的上传，但后续上传仍受生效额度约束。

多用户服务启动后会每分钟分批清理已过期的账号令牌、会话、应用访问票据及上传配额预留；每张表每次最多清理 1,000 条，不删除账户、应用和分享历史。清理失败后会在下一轮重试；示例默认不收集容器日志，因此部署者需要另行建立经脱敏的错误监控。此定期清理不处理磁盘上的上传残留。

示例 Compose 为避免意外留存私密访问数据，关闭了容器日志；这也意味着清理任务失败等服务错误不会通过 `docker logs` 留存。部署者若需要集中日志，应先审查并脱敏应用和代理输出，限制访问与保留时间，禁止采集密码、Cookie、令牌及带敏感参数的 URL，再配置日志驱动和告警。不能把健康检查成功当作全部后台任务正常的证据。

## 准备

1. 在经过审核的源码副本中构建。仓库的 `.dockerignore` 排除默认数据、配置、日志和临时目录；构建上下文仍可能包含其他位置的备份或敏感文件，构建前应检查并移出。以下命令不执行公网启动。
2. 复制 `deploy/nginx.example.conf` 到源码目录之外的受限路径，替换示例域名；将证书放在独立受限目录下的 `admin/fullchain.pem`、`admin/privkey.pem`、`content/fullchain.pem`、`content/privkey.pem`。不得把私钥放入构建上下文或版本库。证书轮换后需重新加载 Nginx。
3. 在源码目录之外创建只有运维可读的 Compose 环境文件，例如 `/secure/hostlet.env`，按下列键填写真实值；不要将真实凭据写入示例文件、版本库或命令历史。`APP_SECRET` 至少 32 字符，使用密码学安全随机值；`ADMIN_PASSWORD` 使用独立的高强度密码。Compose 环境变量会进入容器配置，具有 Docker 管理权限的人可读取；保护 Docker 权限和环境文件。

```dotenv
# 以下仅为格式示意，须在私有文件中替换，不能直接用于部署。
ADMIN_PASSWORD=REPLACE_WITH_PRIVATE_PASSWORD
APP_SECRET=REPLACE_WITH_AT_LEAST_32_RANDOM_CHARACTERS
ADMIN_ORIGIN=https://admin.example.org
PUBLIC_BASE_URL=https://pages.exampleusercontent.net
NGINX_CONFIG=/secure/hostlet-nginx.conf
TLS_DIR=/secure/hostlet-tls
MULTIUSER_ENABLED=false
REGISTRATION_ENABLED=false
APPS_DOMAIN=
SMTP_HOST=
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_FROM=
SMTP_USER=
SMTP_PASSWORD=
```

多用户启用时设置 `MULTIUSER_ENABLED=true`、`APPS_DOMAIN=apps.exampleusercontent.net`，并按实际环境填写 `SMTP_HOST` 和 `SMTP_FROM`；需要认证时填写 `SMTP_USER` 和 `SMTP_PASSWORD`。SMTP 安全模式仅支持 `starttls` 或 `tls`，端口分别通常为 587 或 465。需要开放注册时另设 `REGISTRATION_ENABLED=true`；已有平台设置可能覆盖注册默认值。确认 SMTP 出站网络可用。`ADMIN_ORIGIN` 必须是精确 HTTPS origin；`ADMIN_ORIGINS` 在 Compose 中设置为同一值，`COOKIE_SECURE` 固定为 true。

账号验证、密码重置和不活跃清理提醒邮件均包含中英文说明。上线前应向目标邮箱实际发送测试邮件，检查主题、正文、链接及垃圾邮件过滤；SMTP 接受邮件不保证最终送达。

公开应用的访客可以从管理站点首页的“举报应用”进入 `/report`，粘贴应用地址并提交举报；部署者应在其公开服务说明中公布该入口。表单仅使用地址中的应用标识，地址的路径、查询参数和片段不会作为举报内容提交；托管页面本身不会被插入举报控件。

本机可选邮件协议演练：将 `HOSTLET_OPENSSL` 设置为 OpenSSL 可执行文件的绝对路径，运行 `node --no-warnings=ExperimentalWarning test/isolation-lab/smtp-lab.mjs`。2026-10-29 已在授权的 Linux ARM64 服务器上重新通过。测试仅监听本机，使用临时自签名证书和合成账号；对测试客户端显式信任该临时证书，并检查直接 TLS、STARTTLS、认证、收件人拒绝、证书不受信任及禁止降级，还通过实际邮件内容完成账号验证与密码重置。它不连接真实邮件服务或外部收件箱，不能替代目标环境的 SMTP 投递与证书验证。

## 审查、构建和运行

在干净源码副本根目录、具备 Docker 和 Compose 的机器上执行。以下配置检查不会启动服务；`--quiet` 避免将插值后的凭据打印到终端。构建需要拉取基础镜像及 npm 依赖，不访问应用数据卷；不要把构建日志或完整 `docker compose config` 输出公开。

```sh
docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml config --quiet
docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml build
```

检查实际域名、证书、网络隔离、权限和日志策略后，由运维明确决定是否执行以下命令；它会启动服务并公开配置的 HTTPS 端口（默认 443）。不要在未授权的机器或公网环境中执行。

```sh
docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml up -d
docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml ps
docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml exec nginx nginx -t
```

在受控环境核对证书和域名、未知 Host 拒绝、后端不能被非可信来源直连、管理与内容端口路由、上传、重启后数据、私有访问及静态资源；对多用户场景还需检查邮件、工作空间、共享和浏览器隔离。上述命令本身不构成验收。Nginx 配置和证书变更后先执行 `nginx -t`，成功后执行 `docker compose --env-file /secure/hostlet.env -f deploy/compose.yaml exec nginx nginx -s reload`；检查续期和重载结果。

## 日志、资源与数据

示例关闭 Nginx access log、将 error log 指向 `/dev/null`，并关闭两个容器的 Docker 日志驱动；不记录 URL、请求体、Cookie、授权头或代理错误中的敏感令牌。关闭代理请求缓冲并关闭代理缓存；仍须检查外层代理、CDN、WAF、监控、错误跟踪和主机日志，禁止记录这些敏感内容。应用可能向 stderr 输出异常，示例不收集它；如另行启用日志，必须先实现并验证脱敏。关闭日志会降低故障排查能力，需另建不含敏感数据的监控方案。

应用默认单文件上传上限为 50 MiB，Nginx 的 52 MiB 是含 multipart 开销的请求体上限，并非替代应用配额；工作空间配额可能更小。标准 ZIP 另限 4,000 个目录条目（包括文件夹）、其中最多 2,000 个文件、单文件解压 25 MiB、总解压 100 MiB；ZIP64 暂不支持。ZIP 上传会预留当前可用存储，最多 100 MiB，并在解压时按预留额度限制实际写入；因此低于 100 MiB 的空间也能上传放得下的 ZIP，同空间的其他并发上传可能需要等待预留释放。磁盘还需容纳数据库、历史版本、上传临时文件及备份；请监控空间并设置外部容量和流量限制。两个服务配置 `unless-stopped` 自动重启；应用数据保存在名为 `hostlet-data` 的 Docker 卷中，Compose 项目名变化会改变实际卷名。不要使用 `down -v` 或删除该卷。

工作空间托管资源的单次后端响应最长为 5 分钟，超时会中断响应，以免停滞的连接无限期阻塞维护；极慢的下载可能需要重试。反向代理如果缓冲响应，此限制衡量的是后端到代理的传输时间，不限制代理到访客的连接时间；仍需按环境设置代理超时、连接数限制和监控。

SQLite、资源和上传临时目录均位于容器内固定路径 `/var/lib/hostlet`。备份和恢复必须停止所有写入者，完整保存同一时刻的数据卷及私有配置，恢复时保持容器内绝对路径与兼容版本；不要只复制运行中的 SQLite 文件。操作步骤和一致性检查见 [SQLite 迁移与备份恢复](superpowers/2026-10-27-database-migration-backup.md)。实际卷的备份、恢复与演练须由运维在授权环境完成。
