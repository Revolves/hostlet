# 阶段 0：SQLite 迁移与备份恢复

## 迁移约定

`openDatabase` 在启动时执行迁移。版本记录为 SQLite `PRAGMA user_version`：0 是未登记的旧库，1 是原有单管理员结构；空库创建同一结构。版本 2 为现有页面建立版本记录，3 建立用户及工作空间数据结构，4 增加访问授权修订号，5 建立独立用户会话；后续版本依次增加工作空间应用、托管授权、版本、分享、配额、治理、可见性和清理恢复记录。版本 17 增加旧页面离线迁移记录，版本 18 增加发布恢复记录，版本 19 增加过期记录清理索引，版本 20 增加上传临时文件恢复记录，版本 21 增加团队操作记录，版本 22 增加应用和版本标识，版本 23 增加账号注销恢复记录；升级之前发生的操作不会补录。现有页面不会自动分配给新注册用户。旧库只有完整匹配原始表、索引及约束才登记为 1；结构不明、部分建表或版本高于程序支持范围时拒绝启动，保留原数据供排查。已版本化数据库不重新建立基线。以后按顺序添加不可变迁移，迁移函数只能执行支持事务回滚的操作，不得自行提交事务、修改版本或进行外部文件操作；每次发布都应测试从所有受支持版本升级。

版本 24 增加 API 凭据表及密码变更时清除凭据的触发器；该版本还需在目标部署环境完成备份及升级演练。

迁移在 `BEGIN IMMEDIATE` 内重新读取版本并一次性提交结构和版本，等待写锁最多 5 秒；锁超时或迁移异常时启动失败，退出事务后可重试。SQLite 的事务日志负责数据库事务中断恢复。锁只协调 SQLite 写入：**旧版本程序不知道版本号，不能阻止它在迁移完成后继续运行**。升级前必须停止全部旧实例、后台任务和其他写入者，并保持停止直至备份、升级和检查完成；不要混用不同版本。迁移事务不包含上传文件、配置或数据库外的变更。

## 离线备份

1. 停止全部应用实例和写入者，确认数据库连接已关闭。记录部署版本、实际 `DATA_DIR`、绝对路径及配置文件位置。不要运行在线文件复制；WAL 模式下单独复制 `.sqlite` 可能遗漏已提交数据。
2. 将整个数据目录（包含 `hostlet.sqlite`、可能存在的 `-wal` / `-shm` 和 `storage/`）及 `.env` 复制到独立、受限访问的备份目录。使用文件系统复制工具检查错误并核对文件清单和哈希；保留不可覆盖的原始备份，避免备份中包含明文密钥被泄露。
3. 在隔离的临时目录恢复一份副本，使用相同版本的 Node 打开副本，检查 `PRAGMA integrity_check` 返回 `ok`、`PRAGMA foreign_key_check` 无结果，并核对页面数、私有状态、资源文件和配置。数据库中 `release_dir` 是绝对路径；隔离演练不要启动会访问真实路径的应用。数据库和资源必须来自同一次停机快照。
4. 完成备份核验后，再对正式库升级；升级失败先保留现场和原始备份，排查后重试或按下述步骤恢复。不能假设新旧版本兼容或直接降级。

## 恢复

停止所有实例和写入者。先将故障现场另存，以便排查；从同一备份集恢复完整数据目录和 `.env`，包含所有 SQLite 关联文件及资源文件。恢复到原来的绝对数据路径，否则 `release_dir` 仍指向旧位置：需要先单独制定并验证路径迁移方案，不能直接投入运行。确认域名、密钥、文件权限和部署版本一致；在隔离环境检查数据库完整性、外键、页面记录和对应资源。确认无误后才启动与备份兼容的程序版本。恢复会回退到备份时刻，之后的数据需另行处理。

## 本次临时副本演练

执行 `node --no-warnings=ExperimentalWarning --test test/database.test.js`。测试只在系统临时目录生成旧结构、私有页面及数据库副本；停止连接后复制备份，子进程在迁移事务中退出，验证版本和新表回滚，再恢复副本并检查 SQLite 完整性及私有状态。并发测试持有旧写入事务，同时启动三个迁移进程，验证写入提交后各进程成功及数据保留；另测试异常回滚、重复启动、未知结构和未来版本拒绝。

本次演练是合成数据和单机 SQLite 层验证，未访问用户实际 `data`、真实密钥或资源文件；未完成真实部署的完整目录恢复、应用资源访问和跨机器/断电测试。真实备份与恢复仍需运维在授权环境中执行并记录。

另可执行 `node --no-warnings=ExperimentalWarning --test test/backup-restore.test.js`：在系统临时目录中用合成账号上传私有 ZIP，停止服务并复制完整数据目录，删除原页面后重新停止服务，再将备份恢复到原绝对路径。演练重启应用后检查 SQLite 完整性和外键、账号会话、私有访问授权及嵌套 CSS 资源。此测试使用本机 HTTP、模拟邮件和合成配置，不代表真实生产卷、TLS、邮件或跨机器恢复已经通过。
