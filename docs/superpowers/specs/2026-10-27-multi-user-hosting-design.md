# Hostlet 多用户应用托管设计

日期：2026-10-27

## 目标与范围

Hostlet 是一个开源的前端应用托管平台。官方提供面向中国大陆用户的在线体验实例，任何人可以注册；其他人可以自行部署，并由实例管理员决定是否开放注册。目标用户是个人创作者，以及需要分享和共同管理演示、原型的产品和设计团队。

首版只托管 HTML、CSS、JavaScript 及静态资源，不运行用户提供的服务端代码，也不提供应用数据库、业务 API 或模型服务。应用可以在浏览器中请求创作者自行提供的外部服务，是否成功取决于目标服务的跨域策略等条件。界面提示创作者不要将私密密钥放入前端代码。

核心成功路径：注册并验证邮箱，创建或加入工作空间，上传应用，访问私有应用或创建分享，更新版本，并在必要时回滚。

## 部署与总体架构

首版以单机部署为基线，继续使用 Node.js、React、SQLite 和本地文件，抽出清晰的元数据与文件存储边界，为将来支持其他实现留出空间；首版不承诺已支持 PostgreSQL、对象存储或多实例部署。官方体验实例和自部署实例使用相同的核心功能，注册、额度、保留和邮件等策略由实例管理员配置。

管理端和用户应用使用隔离的域名。每个应用使用稳定、唯一的独立子域名，应用间及管理端使用不同的浏览器 origin；生产部署要求通配符 DNS 和 HTTPS。应用标识不得与平台保留域名或其他应用冲突，删除后是否允许复用必须有明确保护策略，避免旧链接意外指向其他用户的内容。反向代理只将管理域名转发至管理服务，并将应用域名转发至内容服务。

浏览器 origin 隔离只是安全边界的一部分。实施前需要设计并测试认证、Cookie 域与路径、跨域请求、服务工作线程、重定向及可执行资源的隔离；不能简单放宽当前 CSP 沙箱后就认定安全。现有应用兼容性与隔离策略需要通过真实浏览器验证。平台不应在用户应用所在域上暴露管理会话或管理 API。

## 账号和工作空间

用户通过邮箱、密码注册，验证邮箱后使用平台；支持邮件找回密码。实例管理员配置邮件服务及开放注册开关。密码安全存储，验证和重置链接单次使用且有期限；系统应限制登录、注册、验证邮件和找回密码请求频率。

每个用户拥有个人工作空间，也可以创建团队工作空间。工作空间包含应用、成员和审计信息。团队默认不在公开目录展示，提供申请加入链接；已注册用户提交申请，由所有者审批。申请链接支持失效和重新生成，申请提交应受限流控制。待审批用户不拥有空间访问权限。

角色及权限：

| 角色 | 权限 |
| --- | --- |
| 所有者 | 管理工作空间、成员和角色，以及工作空间中的应用；审批加入申请 |
| 编辑者 | 查看、创建、更新和回滚应用，管理其分享设置 |
| 查看者 | 查看工作空间内容及其私有应用，不修改应用或成员 |

首版不引入单独的团队管理员角色；所有者承担审批及成员管理。工作空间至少保留一名所有者，移除、退出和角色变更不得使空间无所有者。应用管理 API 每次按当前成员关系和角色授权，不能仅凭界面隐藏按钮实现隔离。个人空间只属于对应用户；系统管理员的处置能力另行审计。

## 应用、版本和分享

用户上传单个 HTML 文件或 ZIP。平台检测文件格式、大小和安全路径，识别可用入口；发现多个候选入口时由用户选择，缺失入口、资源路径或不兼容情况给出可操作提示。安全检查保留路径穿越、符号链接、特殊文件及解压体积限制。上传完成、检查通过后才切换当前版本；失败时保留原版本。

每个应用默认私有，空间成员依据角色访问。发布者可选择公开访问，或设置独立于账号及管理员凭证的访问密码；分享访问权限可撤销。具体授权方式必须覆盖 HTML 及嵌套 CSS、JavaScript、图片等资源，避免泄露管理凭证。密码保护不是对已交付给访问者的内容进行防复制保护。跨域认证与分享令牌的实现应在技术设计中确定，并在浏览器测试泄露、过期、撤销及跨应用访问。

应用更新后地址保持稳定，保留有限历史版本并支持回滚。版本数量和存储使用计入配额；删除应用及清理历史版本应明确影响和确认。首版不承诺实时协同编辑源文件：团队共同管理发布、设置和版本，编辑者上传新版本。

应用代码在访问者浏览器运行，浏览器本地存储属于访问者和应用 origin；平台不提供跨设备同步或共享应用数据。外部 API 的认证、密钥和数据存储由应用提供方负责。

## 管理、额度和保留策略

实例管理员可配置开放注册、邮件服务、上传大小、应用数量、存储额度及数据保留策略。提供合理默认值，官方实例按试用规模配置；配额检查需要覆盖版本文件和正在进行的上传，并在超额时说明原因和处理办法。带宽限制和精确用量计费不属于首版承诺。

保留策略支持长期保留或按不活跃时间清理。启用清理时，管理员配置清理周期、通知提前量及活动判定；注册和管理界面展示当前规则，清理前通过邮件通知。管理员配置邮件不可用或通知失败时，不应悄然按已通知处理；实现需要明确可重试、审计和失败处置。

公共实例提供举报入口及管理员审核、停用应用的能力。记录必要的管理操作和状态，避免将访问密码、令牌等敏感信息写入日志。正式对外服务前，应根据实际部署和服务形式完成适用的备案、隐私与内容治理要求核查。

## 数据与迁移

元数据至少包括用户、验证和会话、工作空间、成员与加入申请、应用、版本、分享授权、实例设置、举报和审计事件。应用和文件必须绑定所属工作空间，所有查询与写入按空间授权。数据库迁移有版本记录、备份及失败恢复步骤。

现有单管理员数据的迁移不得隐式公开原有私有页面或把原管理员密码变成分享密码。升级前备份数据库、文件和配置；迁移流程由部署者显式选择或创建接管账号与个人空间，检查应用域名及访问设置后再启用。迁移失败应保留原数据和恢复路径。现有私有页面的旧授权链接在迁移时失效，并提示重新配置分享。

文件发布、元数据切换、回滚和删除需定义崩溃恢复及孤儿文件清理规则，避免文件与数据库状态不一致。备份覆盖数据库、应用文件及必要密钥，并通过恢复演练验证；恢复步骤说明域名和绝对路径变化的处理。

## 验收

- 个人用户完成注册、邮箱验证、登录、上传、私有访问、分享、更新及回滚。
- 两个独立用户和工作空间之间，API、文件、历史版本和私有分享无法越权访问；团队申请、审批、角色变更、移除和最后所有者保护符合规则。
- 在真实浏览器中验证各应用独立 origin、本地存储、静态资源和外部 API 访问；验证管理端会话不会被应用读取或滥用，并覆盖私有资源、分享撤销和过期。
- 覆盖异常 ZIP、配额超限、重复入口、上传中断、数据库或文件写入失败、版本回滚和备份恢复。
- 验证注册开关、邮件验证及找回密码、限流、清理通知失败、举报和管理员停用。
- 在桌面与移动端验证核心管理流程；分别记录单元/API 测试、构建、浏览器验收和部署恢复演练结果。

首版不包含付费、应用服务端执行、平台数据库服务、自定义域名、公开团队目录或多人实时编辑。上述能力可在实际需求得到验证后独立设计。
