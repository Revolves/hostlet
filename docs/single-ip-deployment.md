# 单 IP 部署（受控试用）

单 IP 模式面向相互信任的个人和团队，目前处于受控试用阶段，不适用于开放注册的不可信多租户。入口及内容服务要求 HTTPS；部署者需要提供 IP 匹配的证书，本配置不提供证书签发或续期服务。测试证书、生产证书与客户端信任应分别验收。

目标是一个独立 Compose 项目：管理端 `https://<IPv4>:30006`，内容端 `https://<IPv4>:30007/p/<应用ID>/`。Nginx 共用一套覆盖该 IP 的证书，分别转发到应用容器的 3000 和 8080 端口；应用端口不直接发布。管理和内容服务由同一个非 root Node 应用容器提供，代理另用一个容器。容器、网络和数据不能与现有部署混用，也不迁移现有数据。

## 信任与安全边界

- 只允许可信成员上传可信页面及其依赖。不同页面位于同一个内容 origin，共享 localStorage、IndexedDB 等浏览器资源；页面可在用户已有权限下向其他页面发请求。路径和应用 ID 前缀都不提供浏览器级隔离，不适合不可信多租户。
- 管理与内容端口不同，但浏览器 Cookie 不按端口隔离。内容代理仅转发当前页面的 `iphost-member-w-<32位小写十六进制>` 和 `iphost-share-w-<32位小写十六进制>` 会话，值须为 43 位 Base64URL 字符；其他页面及管理身份 Cookie 不转发。提取之前，代理对重复的同名 IP 会话 Cookie 返回 400，包括值无效的情况；即使重复项属于其他页面也会拒绝。示例不支持旧版 `hostlet_access_*` 页面授权。客户端仍可伪造 Cookie，白名单不保证管理 Cookie 防碰撞，也不阻止内容响应设置 Cookie。上线前必须实现并实测服务端 Host、Origin、CSRF、所有敏感读取和写入、Cookie 覆盖及名称碰撞防护，不得把代理过滤当作完整隔离。
- 代理覆盖 `X-Forwarded-For`、`X-Real-IP`、`X-Forwarded-Host`、`X-Forwarded-Proto` 和 `X-Forwarded-Port`，清除 `Forwarded`，使用直接连接地址，不信任客户端传入的转发链。此配置假定 Nginx 直接面向客户端；若前面还有代理，不能直接沿用，必须重新设计并验证信任链。仅信任本项目网络内 Nginx 的固定地址，其他容器不得加入该网络。
- Nginx 关闭访问日志，并将错误日志写入 `/dev/null`；容器日志驱动关闭。应用安全日志仍持久化在专用数据目录，遵循 [安全日志说明](security-logging.md)：不得记录 Cookie、Authorization、票据、密码、请求体、完整 URL、查询参数或邮件链接。其他代理、监控和故障排查日志同样须脱敏并限制访问；关闭容器日志会降低故障排查能力。
- 公开注册固定关闭；仅设置环境变量不证明持久化配置或管理接口无法重新开启。需先实现并验证服务端强制关闭和安全的管理员控制开户方式；当前多用户配置还要求 SMTP，不能假定新实例已经有可登录账号。

## 审查配置

以下为未来实施前的准备要求，不是启动指令：

1. 确认实际 IPv4、两个端口和证书。将 Nginx 示例的两个 `192.0.2.10` 替换为同一个实际 IP；必须与 `ADMIN_ORIGIN=https://<IPv4>:30006`、`SINGLE_IP_CONTENT_ORIGIN=https://<IPv4>:30007` 完全一致。代理检查原始 Host 中的 IP 和对应端口，再将其原样传给应用；不接受缺端口或其他主机名。IPv6 未在此草案中支持。
2. 自行提供 IP 地址匹配且被目标客户端信任的证书及私钥，置于专用目录的 `fullchain.pem`、`privkey.pem`。目录只读挂载到 Nginx，妥善限制宿主机私钥访问。不得假定端口 80/443 可用，也不得假定公开 CA 可为目标地址签发或自动续期；测试自签名证书和真实客户端信任分别验收。
3. 选择全新专用的绝对路径作为 `IP_DATA_DIR`，预先创建空目录，不使用符号链接或现有数据目录，并确保 Dockerfile 中的 `node` 用户可读写。绑定挂载不会自动创建路径；应用数据库、上传文件及安全日志仅写入该目录。配置文件和证书目录单独只读挂载，不要把密钥或环境文件放入数据目录。备份、恢复和目录所有权均需另行验证。
4. 设置独立项目名，例如未来执行 Compose 时明确指定 `--project-name hostlet-ip-<唯一标识>`；不得使用现有项目名。`IP_SUBNET` 选择与宿主机路由及所有 Docker 网络均不重叠的专用 IPv4 子网，`IP_PROXY_ADDRESS` 选择其中未占用且可用的固定地址；两者无默认值。检查网络名、子网、路由、30006/30007 端口和数据目录均无冲突；如有冲突，停止并重新选择，不删除或修改已有容器、网络或数据。不要使用 30008。
5. 在访问受限的独立环境文件中配置 `ADMIN_PASSWORD`、至少 32 字符随机 `APP_SECRET`、上述两个 origin、`IP_DATA_DIR`、`IP_NGINX_CONFIG`（审查后的 Nginx 配置绝对路径）、`IP_TLS_DIR`、`IP_SUBNET`、`IP_PROXY_ADDRESS`、`SMTP_HOST` 和 `SMTP_FROM`；按需配置 `SMTP_PORT`、`SMTP_SECURITY`、`SMTP_USER`、`SMTP_PASSWORD` 与日志保留期。环境文件含秘密，不要提交或输出。SMTP 邮件及其中的管理地址也需单独验证。

在正式运营之前应完成目标环境安全与恢复验收；`docker compose config` 的输出可能包含密码，不要保存或分享。不要因为语法检查通过就视为生产验收通过。
