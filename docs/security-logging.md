# 安全事件日志

服务默认将脱敏后的接口请求结果写入 `DATA_DIR/security-logs/`，每个 UTC 日期一个 `security-YYYY-MM-DD.ndjson` 文件，默认保留 180 天，可用 `SECURITY_LOG_RETENTION_DAYS` 调整为 1–3650 天。文件以追加方式写入；目录已存在时也会在写入前收紧为仅运行用户可访问，Linux 上目录模式为 `0700`、文件为 `0600`。清理只处理符合 `security-YYYY-MM-DD.ndjson` 名称的普通文件，不会遍历其他目录。

每条记录只包含服务器生成的字段：

```json
{"time":"2026-10-29T12:00:00.000Z","event":"http_request","method":"POST","route":"/api/account","status":202,"durationMs":12,"client":"192.0.2.10"}
```

`route` 是固定的粗粒度模板，例如 `/api/account`、`/api/workspaces`、`/app/exchange` 和 `/legacy/page`，不包含查询参数、片段、分享令牌、加入令牌、应用路径或文件名。日志不读取请求体、Cookie、Authorization、密码、邮件令牌或票据；`client` 是服务端经过可信代理配置解析后的地址。管理端记录 API 请求，内容端记录票据交换和错误状态，不把正常资源读取的全量访问日志写入该目录。

## 运维要求

- 备份数据目录时必须一同备份安全日志，并保持文件访问权限；恢复时先确认日志目录不是符号链接。
- 监控数据卷剩余空间、日志文件数量、最近写入时间和错误告警。单进程同步写入是有界小记录，不是集中式日志系统；高流量实例应在可信入口增加经过脱敏的采集、访问控制、不可篡改保存和告警。
- 默认保留 180 天只是运维基线，不自动证明满足特定地区、行业或业务的法律要求。运营者应按实际适用要求确认期限、访问人员、查询流程、事件响应和删除规则。
- 不得用该日志记录完整 URL、请求体、Cookie、密码、账号令牌、分享令牌或邮件链接。不要直接开启 Nginx 全量访问日志或错误跟踪来替代本设计；如另行启用，必须同样脱敏并限制访问。
- 进程崩溃或磁盘满时可能出现日志写入失败，应用不会把日志当作用户请求成功的前置条件；运维必须通过外部监控发现缺失，而不是声称日志具备不可丢失保证。

这不是网络运行日志或安全监测的完整合规方案；真实公网部署仍需完成代理、监控、告警、访问审计、恢复演练和适用的备案/治理评估。
