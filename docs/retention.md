# 独立保留策略与删除恢复协议

保留策略默认为长期保留；管理员可启用按不活跃时间清理。标准服务入口在启动后每小时扫描，停止时等待进行中的扫描完成。没有符合清理条件的应用且没有待恢复删除记录时，扫描不会进入维护状态；需要清理或恢复时仍会排空已有操作并重新核验。通知和删除已接入，并在临时数据上测试；真实 SMTP、代理和部署故障恢复仍需验收，不要将本协议视为已具备生产条件。

## 保留通知

数据库迁移安装 `retentionSchema`；所有写连接必须启用 SQLite 外键并保留这些触发器。无设置或长期保留不通知、不删除。以页面 `updated_at` 的 UTC ISO 时间计算非活跃，浏览访问不算活动；每个 owner 都必须有已验证邮箱，否则页面跳过。

批次持久化页面版本、更新时间、策略和 owner 指纹及投递状态；策略、页面、成员或邮箱变更使批次失效。提前通知期限至少为一天且小于不活跃期限。SMTP 必须确认收件人被接受才算成功，失败由下一次扫描重试；日志仅记录脱敏失败计数。纯 SMTP 不能保证恰好一次，重试可能产生重复邮件。每位 owner 都获得完整通知期后才能删除；删除与审计记录在同一数据库事务中提交。

启用不活跃清理时，缺少有效所有者、已验证邮箱或必要页面元数据的应用会被跳过，并计入最近一次扫描的“需要检查的应用数”；通知失败和删除失败分别计数。管理员可在服务状态中查看汇总和受影响应用的标识、空间标识及问题类型，检查后等待下一次扫描。列表按当前数据分批检查，可能与最近一次扫描的结果不同；不显示邮箱或令牌。扫描状态仅存在于进程内，重启后清零，也不会主动发出告警，需结合外部监控与运维排查。

## 删除和恢复

`server/workspace-deletion.js` 导出 `deletionJournalSql`，已纳入数据库迁移。日志记录页面、工作空间、版本、绝对存储根目录以及程序生成的隔离标识；先提交日志，再将页面目录重命名到同一 `sites` 内的隔离目录。随后使用 `BEGIN IMMEDIATE` 重新核验页面、工作空间、存储标识和版本，再调用 retention 提供的同步校验函数，检查当前策略、通知和到期时间，最后删除页面记录并提交。提交成功或失败后都尝试恢复：页面仍存在时恢复原目录；页面已删除且没有其他页面引用存储标识时才清除隔离目录。冲突、无原目录及隔离目录、根目录不符、路径含链接或特殊文件时拒绝处理并保留日志，供人工排查。`recover()` 可重复执行；任何残留日志会阻止后续删除。启用多用户时，启动会在监听请求之前恢复该日志，再恢复历史版本清理记录。

内部协调示意：

```js
const deletion = createWorkspaceDeletionService({
  db, storageRoot, assertQuiescent: () => maintenanceIsActiveAndDrained(),
});
// 在启动对外服务前，或进入并排空维护态后：
deletion.recover();
const retention = createRetentionService({ db, sender, deletion });
// 通知在维护态之外发送；恢复和清理在排空后执行。
await retention.notify();
// 后续清理须在维护态中执行。
```

必须由宿主强制单机、单进程和存储目录独占，进入维护态后拒绝新页面上传、替换、回滚、管理删除和托管读取，并等待所有已有请求、文件流及异步清理完成；恢复完成前不得启动这些操作。`assertQuiescent` 是宿主的可信断言，不会自行加锁。`server/maintenance.js` 的进程内维护门已连接到工作空间、账号、分享、平台管理及托管服务；上传、工作空间删除、账号和分享的异步操作会在断开连接后继续计入活动数。用户发起的工作空间应用删除也会先进入维护态并使用此日志，删除操作与账号身份一并记入审计。标准服务入口使用数据目录占用标记限制协作实例；该标记不能阻止直接写入的外部进程。生产故障演练仍未完成。

存储根、SQLite 数据库及祖先目录必须由服务独占和保护；不能允许其他进程或不可信用户替换目录、创建链接、修改日志或直接写数据库。路径检查无法消除这种外部对手造成的检查后替换竞态。所有数据库连接必须开启外键；应使用持久磁盘及合适的 SQLite 同步设置，并在同一文件系统内隔离。这里的故障测试覆盖进程退出和 SQLite 提交失败，未证明断电、内核崩溃、磁盘损坏或目录元数据落盘顺序；尚无跨平台目录 fsync、自动运维告警或修复冲突的工具，不能宣称断电原子性或生产就绪。`onStage` 仅供故障注入，不应在生产注入。

测试使用独立临时目录及数据库，不读取真实 data。上线前仍需在目标环境检查独占保障、邮件投递、迁移和备份、文件权限、符号链接与故障恢复，并完成真实并发读写和异常清理验收。
